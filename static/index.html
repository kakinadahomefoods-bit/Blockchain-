Session controls

Create a subject/class session before recording. An on-chain session prevents writes to unknown classes and rejects duplicate marks.

Faculty attendance override

Use when a camera or face match fails. An override is visibly labelled on-chain; it cannot be disguised as a face scan.

Security note

Local demo recognition can be spoofed with a photo. Blockchain protects record integrity, not the authenticity of the face or camera input. A real deployment needs liveness and manual review.

Live vs manual verification

Face enrolment and face scan are processed by the Python/OpenCV service. The Manual button is a separate faculty override: it requires an explanation and is permanently labelled as manual in the attendance event. Unmarked does not mean absent until the session is closed.

On-chain vs off-chain

On-chainRandom-ID-derived HMAC tokens, timestamps, event hashes
Off-chainStudent names, roll numbers, local-only access by default, biometric templates
Faculty accessPassword + short-lived session, smart contract role in EVM mode

Realistic security guarantees

  • ✓ Detects edits to existing local blocks
  • ✓ Rejects duplicate marks for one session
  • ✓ Preserves correction history
  • ✓ Keeps raw images off-chain
  • ! Does not detect photo spoofing or guarantee accurate recognition
  • ! Single-node local mode is not decentralized and cannot stop full-history replacement by its operator
* Ledger integrity is conditioned on the security of validator keys and, in real Ethereum mode, the chosen network. This is a supervised classroom prototype, not a production biometric system.
